Chapter 1 The Architecture

You've tried AI a few times. Downloaded a tool, used it for a week, forgot about it when the next thing came out. I had the same cycle until I realized the problem wasn't the tool. It was starting from scratch every single time.

Here's the mental model that changed everything for me.

Folder Structure + Brain File + Intelligence Hub = Persistent AI Workspace

LLM vs. Wrapper

The LLM (Claude, GPT, Gemini) is the brain. It reasons, writes, and analyzes. But on its own it has no memory, no access to your tools, and no idea who you are.

The wrapper is the body. Claude Code, Cursor, Windsurf, even a chat window in a browser — these are all wrappers around the same underlying LLM. The wrapper gives the brain access to your files, your terminal, your APIs. Different wrapper, different capabilities. Same brain.

At my company, the engineering team runs an instance called "Code Puppy" — it's the same Claude model, but wrapped in a work-specific context with access to Confluence, Jira, and internal documentation. I run my own instance with access to Slack, meeting transcripts, and team intelligence files. Same LLM. Completely different capabilities, because the wrapper and context are different.

Key insight: You're not "using Claude." You're building a workspace that any LLM can operate within. If you set up the workspace right, you can swap Claude for GPT or Gemini and it still works. The value is in the structure, not the model.

Why setups fail

Most people open a chat window, ask a question, and get a generic answer. Next session, the AI has no memory of the previous conversation. So they lose interest.

The fix is persistent context. A file that sits in your project root and tells the AI who you are, what you manage, and how you think. Every session after that starts differently — the AI already knows your team, your priorities, and your preferences.

That file is called a brain file. Combined with an intelligence hub (a folder of reference files the AI reads before answering) and cron jobs (scheduled tasks that pull data without you asking), you get a system that compounds. The more you use it, the smarter it gets.

Chapter 2 Git + Folder Organization

Everything starts with a folder. Not a fancy tool, not a subscription. A folder on your computer that you version-control with Git.

Why Git for a non-code workspace

You know Git from engineering. Here you're using it for the same reason — you want a history of changes, the ability to roll back, and a remote backup on GitHub. The difference is you're tracking markdown documents, team status files, and intelligence reports instead of source code.

One-time setup

terminal 
mkdir ~/work-hub && cd ~/work-hub
git init
gh repo create work-hub --private --source=. --push

Folder organization — pick your style

There are three solid patterns. Pick whichever maps to how you think.

Option A: PARA Method (what I use)

Tiago Forte's system. Four top-level folders. Everything has exactly one home.

folder structure 
work-hub/
  00-inbox/           # Quick capture, unprocessed items
  01-projects/        # Active work with deadlines
  02-areas/           # Ongoing responsibilities (teams, countries, functions)
  03-resources/       # Reference (templates, intelligence-hub, scripts)
  04-archive/         # Completed or inactive work
  CLAUDE.md           # Your brain file (Chapter 3)
  .gitignore

My workspace has 39 intelligence files, 66 custom skills, and 17 AI agents. It started with exactly this structure and five empty folders. Start simple.

Option B: Domain-First

Organized by team, country, or business function. Good if your 16 people break cleanly into groups.

folder structure 
work-hub/
  brazil-team/
  india-team/
  us-team/
  shared-resources/
  intelligence-hub/
  CLAUDE.md

Option C: Timeline-First

Organized by quarter or sprint. Good if your work is heavily deadline-driven.

folder structure 
work-hub/
  2026-Q2/
    active-initiatives/
    team-status/
    decisions/
  2026-Q1/
  intelligence-hub/
  CLAUDE.md

Whichever you pick, the key rule: the parent folder is the workspace root. The AI will read everything from that root down. So whatever is the top-level folder, build everything inside it.

The .gitignore

.gitignore 
.DS_Store
.env
*.key
personal/
node_modules/

First commit

terminal 
git add -A && git commit -m "Initial workspace structure" && git push

Chapter 3 The Brain File

This is the file that makes the AI stop being generic. It sits at the root of your workspace and the AI reads it at the start of every session.

In Claude Code, this file is called CLAUDE.md. In Cursor, it's .cursorrules. In Windsurf, it's .windsurfrules. Different wrappers, same concept.

What goes in it

  • Your role — title, responsibilities, what you own
  • Your team — names, roles, what each person manages
  • Your priorities — what matters this quarter, what's on fire
  • Your tools — what systems you use (Slack, Jira, Confluence, etc.)
  • Your conventions — how you name files, how you structure documents, how you communicate
  • Routing rules — "when I ask about X, look in folder Y first"

Starter template for a 16-person team manager

CLAUDE.md 
# Workspace Context

## Role
- Title: [Your Title]
- Team Size: 16 people across [countries/regions]
- Reports To: [Manager Name, Title]
- Key Tools: Slack, [Project Tracker], [Meeting Notes Tool]

## Team Structure
| # | Name       | Role           | Location | Focus Area         |
|---|------------|----------------|----------|--------------------|
| 1 | [Name]     | [Role]         | [City]   | [What they own]    |
| 2 | [Name]     | [Role]         | [City]   | [What they own]    |
...

## Current Priorities (This Quarter)
1. [Priority 1 - what and why]
2. [Priority 2 - what and why]
3. [Priority 3 - what and why]

## Intelligence Hub
When answering questions, check `intelligence-hub/` first:
- Team status questions → `intelligence-hub/team-status/`
- Decision history → `intelligence-hub/decisions/`
- Meeting context → `intelligence-hub/meeting-notes/`
- Slack context → `intelligence-hub/slack-digest/`

## Conventions
- Documents: UPPER_SNAKE_CASE.md
- Meeting notes: YYYY-MM-DD_topic.md
- Status updates: weekly, stored in team-status/

How it grows

Start with 20 lines. Add things as you work. When the AI gets something wrong, add a rule to the brain file so it doesn't happen again. My brain file started at 20 lines. It's now 163 lines of core instructions plus 500+ lines of identity, skills, and routing rules.

Don't write it by hand if you don't want to. You can paste this into Claude Code:

prompt 
Interview me and build a CLAUDE.md brain file for this workspace. Ask me about my role, team structure, priorities, tools, and communication preferences. Build the file section by section.

Skills, hooks, and memory (intermediate)

Once the brain file is working, you can add:

  • Skills — reusable prompts that trigger on keywords. Example: typing "draft email" auto-loads your writing style and communication rules.
  • Hooks — scripts that run before or after AI actions. Example: auto-validate every document against your formatting standards.
  • Memory — the AI stores corrections between sessions. Tell it "never use passive voice in emails" once, and it remembers for every future session.

You don't need any of this on day one. The brain file alone gets you 80% of the value.

Chapter 4 The Intelligence Hub

This is the concept that ties everything together. A single folder that the AI reads before making any recommendation or decision.

intelligence-hub/ = your team's ground truth

What goes in it

Reference files that represent the current state of your world. Not every email or Slack message — synthesized summaries that the AI can read quickly.

FileWhat It ContainsUpdate Frequency
team-status.mdWhat each person is working on, blockers, capacityWeekly
decisions.mdRecent decisions, who made them, rationaleAs they happen
meeting-notes/Key takeaways from important meetingsAfter each meeting
slack-digest.mdImportant threads, decisions made in channelsWeekly
priorities.mdThis quarter's focus, what's changedMonthly
country-context/Per-country nuances, regulations, local contactsAs needed

Auto-query routing

In your brain file (Chapter 3), you add routing rules that tell the AI which file to read based on the question type. When you ask "what's the team working on?" it goes to team-status.md. When you ask "why did we decide to do X?" it goes to decisions.md.

Example routing rule (from my CLAUDE.md)
CLAUDE.md routing section 
## Intelligence Hub Query Routing

When answering questions, check intelligence-hub/ FIRST:

| Question Type               | Read This File First              |
|-----------------------------|-----------------------------------|
| Team capacity / who's free  | intelligence-hub/team-status.md   |
| Why we decided X            | intelligence-hub/decisions.md     |
| Meeting follow-ups          | intelligence-hub/meeting-notes/   |
| Slack threads / context     | intelligence-hub/slack-digest.md  |
| Country-specific questions  | intelligence-hub/country-context/ |
| Initiative status           | intelligence-hub/priorities.md    |

Project-level context override

You can also put a smaller brain file inside individual project folders. When you're working inside that project, the AI prioritizes the project-level context over the global one. So a project for "Brazil market expansion" can have its own CLAUDE.md that says "when answering questions in this folder, focus on intelligence-hub/country-context/brazil.md and ignore the global team status."

Start with five files

Don't try to build a 39-file intelligence hub on day one. Start with:

  1. team-status.md — one paragraph per person, updated weekly
  2. decisions.md — a running log of decisions with dates and rationale
  3. priorities.md — this quarter's top 5
  4. meeting-notes/ — a folder for important meeting summaries
  5. slack-digest.md — a weekly summary of important Slack activity

That's it. Five files. The AI now has enough context to give you non-generic answers about your team.

NotebookLM as a research engine

NotebookLM (free from Google) is a second layer. Upload your intelligence hub files, meeting transcripts, or any reference material, and it gives you citation-backed answers without consuming your AI's context window. Think of it as a research library the AI can query when it needs deeper context.

Chapter 5 Connecting Your Tools

Your intelligence hub is only as good as the data flowing into it. This chapter covers how to connect the AI to the tools your team actually uses.

What's an MCP

MCP (Model Context Protocol) is an open standard that lets AI models talk to external tools. Think of it as USB for AI — a universal connector. If a tool has an MCP server, you can plug it into Claude Code and the AI can read from (and sometimes write to) that tool directly.

Available MCPs to explore

Tool CategoryMCP ServerWhat It Does
Google Workspacegoogle-workspaceRead/write Gmail, Calendar, Drive, Sheets, Docs
Slackslack-mcpRead channels, search messages, post updates
Jira / Linear / AsanaVariousRead tickets, update status, create issues
Meeting transcriptsmcp-limitlessSearch Limitless pendant recordings semantically
Confluence / NotionVariousRead/write knowledge base pages
GitHubmcp-githubRepos, issues, PRs, code search

How to add an MCP

terminal 
# Example: add Slack MCP
claude mcp add slack npx -y @anthropic/slack-mcp

# Example: add Google Workspace
claude mcp add google-workspace npx -y google-workspace-mcp

Where to find MCPs: github.com/modelcontextprotocol/servers has the official registry. Search for "[your tool] MCP server" and you'll usually find one.

CLI-Anything

Here's the trick that opens everything up: any command-line tool can become an AI capability. If a tool has a CLI, the AI can call it.

  • Your project tracker has a CLI? The AI can check ticket status.
  • Your company uses a custom deploy tool? The AI can trigger deploys.
  • You use curl to hit internal APIs? The AI can do that too.

You don't need to wait for someone to build an MCP. If it runs in the terminal, Claude Code can run it.

Meeting transcripts: Limitless, Otter, Fireflies

I use a Limitless pendant that records all my meetings and makes them searchable via API. But there are alternatives:

  • Limitless — hardware pendant, always-on recording, API access, semantic search
  • Otter.ai — software-based, integrates with Zoom/Teams/Meet
  • Fireflies.ai — meeting bot, auto-joins calls, transcribes and summarizes
  • Built-in transcription — Teams, Zoom, and Meet all have native transcription now

The pattern is the same regardless of tool: record, transcribe, pull into your intelligence hub, let the AI search and synthesize.

Start with one connection

Don't try to connect everything at once. Pick the tool where you lose the most context (usually Slack or meeting notes) and connect that first. Add more as you build the habit.

Chapter 6 Automated Intelligence

The intelligence hub is powerful when you update it manually. It becomes a force multiplier when the updates happen automatically.

What's a cron job

You know this from undergrad, but the quick version: a cron job is a scheduled task that runs at a set interval. On Mac/Linux, crontab -e opens the scheduler. On Windows, it's Task Scheduler.

Claude Code also has a built-in scheduler (CronCreate) that runs tasks within the AI session.

Patterns I run

WhatWhenWhat It Does
Weekly team status aggregationFriday 2pmPulls Slack + meeting notes, synthesizes into team-status.md
Decision health reportSunday 9amScans decisions.md for stalled items, surfaces them
Morning briefingMonday 7amGenerates a digest of what happened over the weekend
Initiative status monitorDaily 5pmChecks if any initiative has gone silent for >5 days

How to set up a cron job

terminal 
# Open the cron scheduler
crontab -e

# Add a weekly Friday 2pm job:
0 14 * * 5 cd ~/work-hub && python3 scripts/weekly_status.py

# Add a daily 5pm check:
0 17 * * * cd ~/work-hub && python3 scripts/initiative_monitor.py

Starter crons for your situation

With 16 people across multiple countries, I'd start with three:

  1. Weekly team status aggregation — Friday afternoon, pull Slack activity per person, update team-status.md
  2. Daily decision log — End of day, scan for decisions made in meetings/Slack, append to decisions.md
  3. Monthly country review — First of each month, generate a summary per country from the past 30 days

Building blocks first, automation later. I used the manual version of all of this for months before automating anything. The automation makes it faster, but the value comes from the structure. Get the folders and brain file working, use it for a few weeks, then start adding crons when you see what's worth automating.

Remote triggers

Claude Code can also run scheduled agents via "remote triggers" — tasks that fire on a cron schedule even when you're not in a session. This is the equivalent of having an AI assistant that checks things while you sleep.

terminal 
# Inside Claude Code, create a scheduled task:
/schedule create --cron "0 14 * * 5" --prompt "Generate the weekly team status report and update intelligence-hub/team-status.md"

Chapter 7 The Walk-Through

This is the checklist for our call. We'll go through each step together. Estimated total: about 2 hours.

Step 1: Install Claude Code CLI

Requires Node.js first. Install from nodejs.org, then:

terminal 
npm install -g @anthropic-ai/claude-code
claude

Step 2: Create your workspace folder + git init

Pick a name, create the folder, initialize Git, push to GitHub.

terminal 
mkdir ~/work-hub && cd ~/work-hub
git init
gh repo create work-hub --private --source=. --push

Step 3: Choose your folder structure

Pick PARA, Domain-First, or Timeline-First (Chapter 2). Create the folders.

Step 4: Create your CLAUDE.md brain file

Use the template from Chapter 3, or let Claude interview you:

prompt 
Interview me and build a CLAUDE.md brain file. I manage 16 people across multiple countries. Ask me about my role, team structure, priorities, tools, and how I want to communicate with you.

Step 5: First real conversation — verify the AI knows you

Ask it something that requires context. If it answers generically, the brain file needs more detail.

prompt 
What are the top three things I should focus on this week based on my priorities and team structure?

Step 6: Add intelligence hub with 3-5 starter files

Create intelligence-hub/ with team-status.md, decisions.md, priorities.md. See Chapter 4.

Step 7: Connect your first MCP

Start with whatever tool leaks the most context. Usually Slack or Google Workspace. See Chapter 5.

Step 8: Set up your first cron

A weekly team status aggregation is a good first one. See Chapter 6.

Step 9: Iterate

Use it for a week. Add rules to the brain file when the AI gets something wrong. Add files to the intelligence hub when you notice gaps. Connect more tools as you see the value. This system compounds — the more you feed it, the better it gets.
